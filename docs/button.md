# Button · контракт v0.3

## Иерархия и смысл

Четыре иерархии определяют визуальный вес: основная, вторичная, акцентная и тихая. Шесть тонов независимо определяют смысл: брендовый, нейтральный, успех, внимание, опасность, информация. Все сочетания представлены в плейграунде; выбранный тон применяется к матрице состояний и живому образцу.

Тон success обозначает позитивное действие до нажатия. Состояние feedback success сообщает результат завершённой операции. Это разные оси. Недоступность использует общие нейтральные роли, а загрузка сохраняет выбранный акцент. IconButton и SplitButton получают те же тоны через общий Button.

Декоративной полоски нет. Линейный индикатор появляется только при измеримой загрузке с заданным progress. Обычная кнопка использует спокойный объём поверхности и общий фокус без изменения геометрии.

Палитра общая со статусами, но роли действий отдельные: `sys.color.intent.<tone>` → `comp.button.tone.<tone>`. Сплошная и мягкая поверхности, текст, контур и интерактивные состояния связаны ссылками. В светлой и тёмной темах роли выбирают подходящие значения исходной палитры.

## API

```tsx
import { Button, IconButton, Tooltip } from '@basis/ui';
import { Plus, RefreshCw } from 'lucide-react';
import '@basis/tokens/styles.css';
import '@basis/ui/styles.css';

<Button
  variant="primary"
  size="md"
  leadingIcon={<Plus />}
  loading={isCreating}
  loadingLabel="Создаём ВМ"
  onClick={createVm}
>
  Создать ВМ
</Button>;

<Tooltip content="Обновить список">
  <IconButton icon={<RefreshCw />} aria-label="Обновить список" onClick={refresh} />
</Tooltip>;
```

| Параметр                      | Значения / назначение                                                     |
| ----------------------------- | ------------------------------------------------------------------------- |
| `variant`                     | `primary`, `secondary` (по умолчанию), `tonal`, `ghost`                   |
| `tone`                        | `brand` (по умолчанию), `neutral`, `success`, `warning`, `danger`, `info` |
| `size`                        | `sm` = 32 px, `md` = 36 px (по умолчанию), `lg` = 44 px                   |
| `leadingIcon`, `trailingIcon` | Иконки наследуют цвет и размер компонента                                 |
| `loading`                     | Загрузка; фокус сохраняется, повторная активация блокируется              |
| `loadingLabel`                | Необязательный текст при загрузке и доступное имя                         |
| `loader`                      | `cloud` по умолчанию; варианты `orbit`, `dots` для обсуждения             |
| `progress`                    | 0–100, только при загрузке; визуальная полоска                            |
| `disabled`                    | Нативная недоступность, исключение из Tab-последовательности              |
| `aria-disabled`               | Недоступность с сохранением возможности получить фокус                    |
| `feedback`                    | `success` / `error`, управляется потребителем                             |
| `fullWidth`                   | Ширина родительского контейнера                                           |
| `type`                        | `button` по умолчанию; `submit` и `reset` задаются явно                   |

Остальные нативные атрибуты и `ref` передаются настоящему `<button>`. Для переходов используются ссылки `<a>`, не кнопки с имитацией ссылки.

Старый `variant="danger"` сохранён как совместимость и соответствует `variant="primary" tone="danger"`. Новые композиции разделяют иерархию и тон.

## Состояния и асинхронность

- Нажатие вызывает обработчик; сам компонент не отправляет запросов и не меняет бизнес-состояние.
- Приложение выставляет `loading`. Компонент блокирует click, Enter, Space и отправку формы через эту кнопку, пока `loading=true`.
- Загрузка использует `aria-disabled` и `aria-busy`; нативный `disabled` не включается автоматически, чтобы сохранить клавиатурный фокус.
- Для защиты от двух синхронных вызовов до перерисовки приложения используйте блокировку операции. Демонстрационный `useOperation` показывает это через `ref`; серверные операции также требуют своей идемпотентности.
- Обычное и загружаемое содержимое занимают одну ячейку CSS Grid. Компонент резервирует большее из них. Передавайте `loadingLabel` постоянно, а не только в момент начала запроса. Не меняйте подписи на произвольно длинные строки во время загрузки.
- При существенной смене текста после завершения задавайте ширину на уровне контейнера или `fullWidth`, если нужна неизменная ширина всей операции.
- Кнопка с иконкой заменяет её облачным индикатором. У кнопки без иконки индикатор занимает центр; при заданном `loadingLabel` отображается текст с индикатором.
- `progress` визуальный: числовой прогресс и результат нужно озвучивать в отдельном `role="status"` / `role="progressbar"` по сценарию приложения, не спамить каждое изменение процента в live region.
- Success и error показываются компонентом только по явному `feedback`. Отмена операции и решение, когда сбросить результат, принадлежат приложению.

## Клавиатура и движение

Tab перемещает фокус; Enter и Space активируют. Видимый focus-ring не зависит от hover. Tooltip доступен при фокусе и скрывается Escape. В SplitButton работают стрелки, Home/End, Enter и Escape; после закрытия фокус возвращается к кнопке раскрытия.

`prefers-reduced-motion` отключает движение индикаторов. Факт загрузки остаётся виден по индикатору и тексту. В плейграунде есть отдельная пауза анимаций. Пауза не останавливает демонстрационную операцию.

## Использование в композициях

Сортировка, фильтры, действия ВМ и массовые операции используют общий Button. Таблица определяет доступность действия и его данные, но не реализует загрузку, фокус или иконку заново. Для плотной строки 40 px используется кнопка S высотой 32 px.

Опасное действие требует осмысленной подписи. Подтверждение показывается для сценария, где это действительно необходимо; модальное окно и бизнес-логика не входят в Button.
