# Архитектура токенов BASIS 0.4

Архитектура отделяет физическое значение от смысла и от его применения. Изменения доступны дизайнеру без чтения компонентного кода; связи остаются видимыми при экспорте.

## Три слоя

| Слой               | Отвечает на вопрос                   | Пример                                   | Правило                                                           |
| ------------------ | ------------------------------------ | ---------------------------------------- | ----------------------------------------------------------------- |
| Reference / `ref`  | Какое значение существует в системе? | `ref.color.navy.800`                     | Типизированные исходные значения. Не зависят от компонентов       |
| Semantic / `sys`   | Для чего используется значение?      | `sys.color.action.primary.bg.default`    | Назначение и режим; ссылки на исходную шкалу или другую семантику |
| Component / `comp` | Как компонент использует роль?       | `comp.button.primary.background.default` | Ссылки на семантику; прямой переход к палитре запрещён            |

В данных сохраняется ссылка, а не результат её вычисления. Сборка выдаёт CSS-ссылки `var(...)`; инспектор дополнительно показывает итоговое значение. Один и тот же граф используется для сборки и браузерного эксперимента.

Шкалы интервалов, радиусов, шрифтов, иконок, толщин и размеров независимы. Совпадение чисел не служит основанием для объединения. Геометрия тени отделена от её цветовой роли; составной рецепт не дублирует значения. Типографические стили собираются из атомарных семейства, размера, насыщенности и интерлиньяжа.

## Режимы

Цветовая семантика имеет Light/Dark с идентичным набором путей. Геометрия, типографика, поведение и компонентные связи общие. Изменение `comp.button.radius` влияет на кнопку в обеих темах. Изменение `sys.color.action.primary.bg.default` — только на выбранную тему. Изменение исходной палитры влияет на все использующие её роли.

Это не инверсия цветов. Тёмная тема имеет самостоятельную иерархию поверхностей, светлый основной текст, иной контраст основного действия и мягкие статусные фоны. Фирменная палитра сохраняет значения логотипа: navy `#1C2A60`, blue `#0196F0`.

## Токены компонентов

Параметр выделяется на компонентном уровне, когда нужен самостоятельный дизайнерский контракт: состояния кнопки, фон/граница поля, геометрия таблицы, маркеры слайдера. Общие роли остаются общими: не создаём копию текстового цвета или тени для каждого контейнера.

Состояния определяются поведением компонента, а не декартовым произведением всех опций. Размер, иерархия, состояние, содержимое и тема — разные оси. Иконки заменяются экземплярами; они не должны порождать отдельный вариант для каждого символа.

Составной компонент использует базовые. Таблица не получает отдельную кнопку и не переопределяет её внутренние отступы. Ширины столбцов задаются по роли данных: идентичность, статус, число, связь с сущностью, адрес, действия. Это параметры ДС, не пользовательские настройки таблицы.

## Проверки

Сборка отклоняет разорванные ссылки, циклы, несовместимые типы, нарушенное направление слоёв, дубли определений, конфликт CSS-имён, недопустимые значения и различающийся набор токенов тем. Значения имеют описания. Отдельная проверка выявляет несуществующие переменные в стилях и прямые HEX-цвета вне источников.

Поддерживается используемое проектом подмножество DTCG 2025.10: sRGB color, dimension, number, fontFamily, fontWeight, duration, cubicBezier, одиночный shadow, вложенные группы и ссылки по пути. Это не универсальный парсер всех возможных расширений DTCG. Для реального импорта нужен адаптер к конкретному экспортёру Figma.

Контраст проверяется для основного/вторичного/поясняющего текста и текстов четырёх видов кнопок во всех трёх состояниях обеих тем. В плейграунде четыре выбранные пары пересчитываются при эксперименте. Проверки остальных сочетаний, графики, фокуса, масштабирования и вспомогательных технологий нужны при реализации продуктовой библиотеки.

## Управление из Figma

Подготовленный контракт описывает четыре коллекции:

1. Reference: исходные значения, один режим Value.
2. Semantic colors: роли цвета, Light/Dark.
3. Semantic metrics: размеры, ритм, движение, один режим Value.
4. Components: ссылки параметров компонентов, один режим Value.

Контракт содержит пути переменных, типы, описания, предметные scopes, CSS code syntax и ссылки. Типографика и эффекты передаются как рецепты стилей. Поле `figmaFamily` отделяет имя Onest в Figma от имени локального webfont Onest Variable.

Порядок следующего этапа: выбрать рабочий Figma-файл → создать/сопоставить коллекции → проверить aliases, modes и привязки на Button/Input/Table → проверить круговой обмен → закрепить Figma как источник согласованного дизайна. До этого канонический источник — локальные файлы `src/`, а не экспортируемый браузерный эксперимент.

После подключения изменения из Figma должны проходить проверяемый путь: экспорт → нормализация типов/путей → сравнение добавленных, изменённых и удалённых токенов → проверка обеих тем → просмотр влияния → согласование → сборка. Автоматически подменять исходную систему любым JSON из браузера нельзя: эксперимент не является опубликованным дизайном.

## Версионирование

Имена описывают назначение, а не текущий цвет и размер. Переименование или удаление пути является изменением контракта. Для миграций используется временный alias и запись о замене; временные имена не становятся второй палитрой. Новый токен добавляется вместе с назначением, типом, обеими темами при необходимости и примером компонента.

Для публикации следующей версии фиксируются версия источника, checksum графа, изменения семантики/компонентов, результаты проверок и визуальные снимки. Метрики и цветовые режимы проверяются отдельно, чтобы случайная геометрическая правка не маскировалась сменой темы.

Спецификации: [DTCG Format 2025.10](https://www.designtokens.org/tr/2025.10/format/), [Figma Variables](https://developers.figma.com/docs/plugins/working-with-variables/), [режимы переменных](https://help.figma.com/hc/en-us/articles/15343816063383-Modes-for-variables).

## Тон действия и совместимость 0.3

Смысловой тон — самостоятельная ось Button: brand, neutral, success, warning, danger, info. Иерархия задаёт сплошное, контурное, мягкое или тихое представление. Геометрия, фокус, disabled и поведение загрузки общие.

`sys.color.intent.<tone>` хранит роли сплошной и мягкой поверхности, текста и контура. `comp.button.tone.<tone>` ссылается на эти роли. Состояния default / hover / pressed представлены отдельно; 150 пар текста и фона проверяются в двух темах. Цветовой тон действия не заменяет состояние success/error после завершения операции.

Устаревший вариант Button danger сохраняет поведение через основную иерархию и tone=danger. Его прежние токены остаются совместимыми ссылками. Декоративный `comp.button.signature` выведен из системы. При восстановлении браузерного эксперимента эта правка пропускается, остальные сохраняются; исходный черновик резервируется.

## Расширение 0.4

790 токенов. 184 проверки контраста включают Tag, Badge, Message и Chip. У новых компонентов выделены собственные параметры через семантику. Общие Input и Button продолжают отвечать за свои стили внутри составных элементов. Унаследованные компоненты показаны на каждой соответствующей странице.

Avatar, геометрия Badge и ширина CascadeSelect не зависят от совпадающих чисел в шкале отступов и таблице. `comp.status.*` отделён от `comp.badge.*`; старые геометрические правки статусов мигрируют при восстановлении эксперимента без номера версии. Новые эксперименты сохраняют версию источника.

## Консоли ВМ

Постоянно тёмная рабочая область выделена в `sys.color.console.*`, общую для обеих тем. Это не `surface.inverse`, которая меняет смысл при переключении темы. Оболочка использует обычные тематические поверхности. `comp.console.*` связывает эти роли с геометрией `sys.layout.console.*`; повторно используемые кнопки, меню и поля сохраняют собственные рецепты. Описание поведения и связей: [консоли ВМ](vm-consoles.md).
