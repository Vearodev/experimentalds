# Публикация на GitHub Pages

Каталог ДС и демонстрационный портал публикуются одним статическим сайтом. Для публичного репозитория достаточно GitHub Free. Node.js нужен при сборке; работающий сервер приложению не требуется.

## Первый запуск

1. Создайте публичный репозиторий на GitHub. Для переноса текущей папки удобнее пустой репозиторий без автоматически созданных README и `.gitignore`.
2. Отправьте исходники в ветку `main`. Файлы `.github/workflows/pages.yml`, `package-lock.json`, `packages/`, `apps/`, `scripts/`, `test/` и `design/reference/` должны присутствовать в репозитории; готовую папку `dist-pages/` коммитить не нужно.
3. В репозитории откройте **Settings → Pages → Build and deployment → Source** и выберите **GitHub Actions**.
4. Откройте **Actions → GitHub Pages → Run workflow**, выберите `main` и запустите. После успешного задания `deploy` ссылка появится в его окружении `github-pages` и в **Settings → Pages**. Последующие push в `main` обновляют сайт автоматически.

Для текущей папки без Git первый перенос выглядит так; замените `OWNER` и `REPOSITORY` своими значениями:

```powershell
git init -b main
git add .
git commit -m "Prepare BASIS design system for GitHub Pages"
git remote add origin https://github.com/OWNER/REPOSITORY.git
git push -u origin main
```

Персональный токен для workflow добавлять не нужно: используются встроенные разрешения GitHub Actions. Если основная ветка имеет другое имя, замените `main` в фильтрах и условиях `.github/workflows/pages.yml`.

## Адреса

При обычном имени репозитория адрес сайта — `https://OWNER.github.io/REPOSITORY/`.

| Адрес относительно сайта         | Что открывается          |
| -------------------------------- | ------------------------ |
| `/` или `playground.html`        | Каталог дизайн-системы   |
| `cloud-demo.html`                | Обзор облачной платформы |
| `#buttons`                       | Раздел кнопок в ДС       |
| `cloud-demo.html#cloud/vms`      | Реестр ВМ                |
| `cloud-demo.html#cloud/networks` | Реестр сетей             |

Внутренняя навигация использует фрагмент после `#`, поэтому прямые ссылки и обновление внутренних страниц не требуют серверных правил переадресации или обходов через `404.html`. Имя репозитория не зашито в сборку: относительные пути поддерживают `/REPOSITORY/`, корень `OWNER.github.io` и собственный домен. Настройка собственного домена и DNS выполняется отдельно в GitHub.

## Что публикуется и где хранятся данные

Публикуется **только `dist-pages/`**: три HTML-входа, общие JavaScript/CSS, локальные шрифты Onest, логотип и `.nojekyll`. Сжатые ресурсы имеют хеши в именах и используются всеми входами сайта. Исходные карты JavaScript не генерируются. `node_modules`, `.local`, автономные HTML в корне и результаты сборок исключены из Git через `.gitignore`.

В режиме Pages тот же MockEngine работает внутри браузера. Создание ресурсов, задачи, симуляция ошибок и другие реализованные сценарии остаются интерактивными. Изменения хранятся в `localStorage` посетителя; общей серверной базы и синхронизации между пользователями нет. При недоступном хранилище текущая сессия продолжает работать в памяти. Исходные данные восстанавливаются через настройки демо. Реальные облачные сервисы, гипервизоры и терминалы не подключаются.

При публичном репозитории видны и исходники, и опубликованное приложение. GitHub также допускает публичный Pages из приватного репозитория на подходящем тарифе: GitHub Pro для личного аккаунта, Team или Enterprise Cloud для организации. Приватность репозитория не скрывает HTML, JavaScript, CSS и демонстрационные данные, отданные посетителю сайта. [Условия GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages).

## Локальная проверка публикации

Используйте Node.js 24, указанный в `.nvmrc`, и npm:

```powershell
npm ci
npm run build:pages
npm run preview:pages
```

Откройте http://127.0.0.1:4174/basis-preview/ или http://127.0.0.1:4174/basis-preview/cloud-demo.html. Это статический сервер с подпапкой, как на Pages: без HTTP API и без подмены отсутствующих файлов главной страницей. Остановка — Ctrl+C.

Другой путь и порт можно задать явно:

```powershell
npm run preview:pages -- --base /my-repository/ --port 4175
```

`build:pages` проверяет TypeScript и границы ДС, компилирует токены и Vite в режиме `pages`, подготавливает HTML-входы и запускает `pages:check`. Последний проверяет встроенный транспорт, состав результата, ссылки на стили, скрипты, шрифты и логотип через HTTP в корне и двух уровнях вложенности. Тесты транспорта отдельно проверяют работу без сетевого API, восстановление состояния и продолжение работы после ошибки.

Workflow дополнительно выполняет `npm ci`, проверку форматирования, токенов, функциональной карты и весь набор тестов. Pull request только проверяется; публикация разрешена для `main`. Разрешения записи Pages и OIDC выдаются только заданию публикации.

`npm run build` по-прежнему создаёт автономные `playground.html` и `cloud-demo.html` для открытия с диска. `npm run dev` и обычный `npm run preview` используют локальный HTTP mock API. Для проверки именно GitHub Pages используйте `preview:pages`.

## Если публикация не открылась

- `Configure Pages` сообщает, что сайт не найден: выберите **Settings → Pages → Source → GitHub Actions** и повторите workflow.
- Сайт возвращает 404: дождитесь успешного `deploy`, проверьте адрес в **Settings → Pages** и имя ветки. Для стандартного project site нужен сегмент `/REPOSITORY/`.
- Сборка не прошла: ошибка находится в конкретном шаге **Actions → GitHub Pages**. Предыдущая успешная публикация сохраняется.
- Нет общей базы между браузерами: это ожидаемый статический режим. Для общего состояния потребуется отдельный backend.

Официальная документация: [custom workflow GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages), [публикация Vite](https://vite.dev/guide/static-deploy.html#github-pages).
