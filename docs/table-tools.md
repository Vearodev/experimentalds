# Инструменты таблицы · визуальный контракт

В заголовках контекстных окон название и пояснение образуют компактную связку: 20 px и 16 px по высоте строки, между ними 2 px. Это общий рецепт `comp.context-panel.title-line-height`, `description-line-height` и `label-gap`, включая окно «Навигация по списку». У TableSelect сохранён более крупный заголовок 18/24 px; пояснение также 16 px с промежутком 2 px. Изменения действуют одновременно в ДС и портале, без локальных переопределений.

## Единый навигатор и личные наборы фильтров · 16 ноября 2026

Навигация по страницам — единый однострочный блок «‹ Стр. 2 из 5 ⌄ ›» в шапке и подвале. Текущая страница выделена насыщенностью, пояснение и общее число страниц спокойнее. Номер всегда виден без открытия окна. Стрелки листают, счётчик открывает компактный ContextPanel с прямым переходом, быстрым выбором размера страницы и командами «В начало» / «В конец». Постоянных полей ввода и отдельного селекта в подвале нет. Оба экземпляра имеют одинаковую геометрию: кнопки 36 px, минимальная ширина счётчика 112 px. Для длинных чисел резервируется ширина полного номера последней страницы, поэтому переходы не сдвигают инструменты. На узком экране остаётся однострочный счётчик «2/5» и ширина навигатора 128 px.

Слева в подвале — «Записи 13–24 из 128»: диапазон текущей страницы и общее количество после поиска и фильтрации. При последовательной загрузке — «Загружено 24 из 128». На узком экране подпись сокращается до «Всего 128». При пустом результате показывается «Всего 0»; первичная загрузка и ошибка используют общие состояния таблицы без недостоверных чисел. Итоги сохраняются и при навигации только в шапке. Нижняя полоса на общем фоне таблицы остаётся высотой 45 px; счётчики не добавляют второго ряда. Полный диапазон также доступен в подсказке счётчика и в окне перехода.

Вертикального разделителя после сортировки нет. Группы действий разделены отступом. У «Фильтров» появилась объединённая стрелка сохранённых наборов: открыть меню и выбрать название — два нажатия. Фильтр, наборы, сортировка, представление и обновление доступны при массовом выборе. Изменение выбора не сдвигает данные.

В общем окне фильтров две вкладки: «Условия» и «Мои наборы». Сохранение открывает встроенную форму названия, не требует ещё одного окна и не применяет черновик автоматически. Название обязательно, до 64 символов, уникально внутри этого списка без учёта регистра. В набор входит весь текущий набор условий AND, включая скрытые столбцы; незаполненные условия сохранить нельзя. При редактировании отдельной колонки библиотека не показывается — она доступна из общих фильтров.

В библиотеке есть поиск по названию и значениям, сводка условий, отметка совпадающего набора и отдельное меню действий: переименовать, создать копию, обновить текущими условиями, удалить. Удаление находится в действиях конкретного набора, не на первом уровне быстрого меню. Обновление, переименование и удаление можно отменить до следующего изменения или закрытия окна. Полные условия связаны с кнопкой через доступное описание. Применение заменяет только фильтры, возвращает первую страницу и сохраняет поиск, сортировку, группировку, вид, размеры и выбор ресурсов. Сохранение хранит копию правил; дальнейшее редактирование текущих фильтров не меняет шаблон. «Создать копию набора» открывает форму с названием «Название · копия» и копирует именно выбранный набор, независимо от текущих фильтров. Для уже сохранённых условий команда повторного сохранения не показывается. Выбранный набор определяется также по ID: одинаковые условия у копий не смешивают выбор и назначение по умолчанию.

На первом уровне выпадающего меню остаются список наборов, компактный флажок «Запомнить выбор» и управление. Сохранение появляется для новых или изменённых условий. У каждой таблицы и контекста может быть один набор по умолчанию; в меню его обозначает Pin вместо Bookmark в том же месте. Текст условий не меняется, дополнительная подпись не добавляется; пояснение доступно в тултипе. Обе иконки пункта выровнены по центру всего блока названия и описания, место галочки зарезервировано даже в невыбранных radio-пунктах. Переключение флажка не меняет высоту, ширину или положение меню. Сам флажок не имеет отдельного заголовка, подстроки или постоянной фоновой заливки. При следующем открытии таблицы назначенные условия имеют приоритет над временным фильтром сессии, сохраняя остальные настройки реестра. Временный сброс/изменение условий не переписывает набор. Отключение флажка не сбрасывает уже применённые условия. Флажок показывается только для выбранного сохранённого набора и относится именно к нему. После сброса или изменения условий, когда они больше не совпадают с сохранённым набором, флажок скрывается, даже если ранее назначен набор по умолчанию. Само назначение при этом сохраняется; для его изменения нужно снова выбрать набор. При сохранении и в карточках библиотеки этого флажка нет. Удаление назначенного набора снимает назначение; отмена восстанавливает оба. Menu поддерживает независимый пункт-флажок и сохранение меню открытым при изменении настройки, с клавиатурой и восстановлением фокуса.

Это клиентская возможность. Демо хранит версионированные наборы в localStorage отдельно для каждого реестра и его контекста; ДС имеет отдельную библиотеку. Сохранение переживает перезагрузку браузера, изменения синхронизируются между вкладками. Ошибка записи показывается пользователю, без ложного сообщения об успехе. Набор с недоступными полями остаётся виден для переименования/удаления, но не применяется частично. Нарушенная структура не восстанавливается как более широкий фильтр. UI получает управляемую библиотеку; локальное хранение реализовано отдельным адаптером.

Подвал использует `comp.table.footer-*`, навигатор — `comp.table.navigator-*`, библиотека наборов — `comp.table-tools.preset-*`. Размеры счётчика имеют связи ref → sys → comp, компактное окно — `comp.context-panel.compact-width`. Они ссылаются на существующие системные роли поверхностей, границ, отступов и размеров. Новых универсальных компонентов нет: используются Button, Input, Menu, Tabs, Message и ContextPanel.

## Шапка, карточки и два режима загрузки · 16 ноября 2026

У DataTable единый блок инструментов в ДС и портале: поиск слева; постоянно доступные фильтры и сортировка справа; затем представление, компактная пагинация и обновление. Подпись остаётся у фильтров. Одна ghost-кнопка «Представление списка» 32 px объединяет таблицу/плитки, способ загрузки, поля, группировку и сброс ширины колонок. Вид и загрузка — независимые radio-группы общего Menu. Отдельной капсулы или постоянной заливки у кнопки нет. Поиск в обоих приложениях — общий Input. При массовом выборе заменяется только область поиска и дополнительных действий; фильтры, сортировка, представление, навигация и обновление остаются доступны. Два слоя панели участвуют в расчёте высоты, поэтому строки не сдвигаются.

В меню представления есть «Расположение навигации»: только в шапке, только внизу или в обоих местах. Настройка хранится отдельно от режима загрузки и сохраняется для каждого реестра. Её изменение не сбрасывает страницу, фильтры и выбор. Оба экземпляра вызывают один контракт пагинации. Счётчик резервирует ширину номера последней страницы: переходы между номерами не сдвигают соседние инструменты. Панель перехода валидирует целый номер в допустимых границах, Enter применяет переход; закрытие отбрасывает черновик и возвращает фокус. Размер страницы меняется одним нажатием в панели, сохраняя первый ранее видимый ресурс. В режиме прокрутки тот же блок показывает объём загруженного, даёт загрузить следующую порцию и выбрать её размер.

| Режим         | Данные и поведение                                                                                                                                                                                                                                                                                              |
| ------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| По страницам  | Текущая порция; стрелки доступны сверху и снизу. Переход возвращает прокрутку данных к началу.                                                                                                                                                                                                                  |
| При прокрутке | Порции последовательно добавляются в конец. Наблюдается нижняя граница внутреннего viewport таблицы. В шапке — число загруженных ресурсов. Есть облачный loader, кнопка «Загрузить ещё», повтор при ошибке и завершение списка. Ошибка не скрывает ранее загруженные строки и не запускает бесконечные повторы. |

Переключение режима начинает с первой порции и сохраняет запрос, фильтры, сортировку, группы, видимые поля и выбор по ID. Переключение таблицы/плиток сохраняет текущую страницу или объём загруженных данных; изменение состава полей также не сбрасывает страницу. В портале доступны размеры 12, 24, 48 и 96; в ДС — 4, 8, 12 и 24. При обычной пагинации смена размера открывает страницу, содержащую первый ресурс прежней страницы. При прокрутке размер задаёт порцию; его изменение начинает с первой порции нового размера и отменяет устаревшую подгрузку. Выбор сохраняется. Режим и размер сохраняются в настройках реестра; старые настройки открываются с обычной пагинацией по 12 ресурсов.

### Высота рабочей области

Плитки при любом способе загрузки и таблица в режиме «При прокрутке» занимают всю оставшуюся высоту рабочей области. Шапка, фильтры, группировка и подвал участвуют в раскладке; прокручиваются только ресурсы внутри контейнера. Короткий список, пустой результат и загрузка сохраняют нижнюю границу контейнера. Вложенные вкладки сущности передают доступную высоту реестру. Высота определяется раскладкой, без вычисления отступов от окна в JavaScript.

Обычная таблица с постраничной навигацией использует высоту по содержимому с ограничением области строк. Небольшое число записей не растягивается на весь экран. В ДС плитки и последовательная загрузка показаны в ограниченной демонстрационной области с тем же поведением внутренней прокрутки. Общий контракт `data-fill-height` связывает контейнер реестра, вкладки и DataTable; размеры и оформление компонентов принадлежат общему UI.

### Изменение ширины

Ресайз доступен на правой границе информационных заголовков. Чекбокс 44 px и меню действий 48 px фиксированы и не имеют разделителя. Зона захвата 8 px отделена от кнопок фильтра и подсказки отступом 4 px. Индикатор появляется при наведении, фокусе и перетаскивании. Заголовки и строки меняются одновременно, без анимации ширины. Сначала ширина компенсируется соседней информационной колонкой до её минимума, затем таблица увеличивается с собственной горизонтальной прокруткой.

Минимум обычной колонки — 96 px; сложного заголовка с подсказкой и инструментами — 160 px. Стандартный предел ручного увеличения — 720 px, для закреплённого имени он учитывает доступный viewport. Свободное место таблицы заполняет одна информационная колонка. Размеры сохраняются по ID после завершения жеста; скрытые колонки сохраняют свои настройки. Escape и отмена указателя возвращают исходные размеры. Стрелки меняют размер на 16 px, Shift — на 64 px; Home или двойное нажатие возвращают стандартную ширину одной колонки. «Стандартная ширина колонок» в меню сбрасывает все размеры. Числовых полей ширины в настройках колонок нет.

Геометрия проходит через `ref.size.table.resize → sys.table.resize → comp.table.resize`. Компонентные токены также связывают область захвата, шаг клавиатуры и цвет индикатора с системными размерами и фокусом. Оба представления используют общие состояния запроса и выбора; ресайз применяется только к таблице.

«Выбрать все» означает все доступные ресурсы текущей страницы или все уже загруженные. Новые порции не выбираются автоматически. Группы строятся после фильтрации и перед разбиением на порции: при подгрузке одинаковые группы продолжаются, а счётчик различает загруженное и общее количество. Изменение запроса, режима или обновление отменяет влияние устаревшей подгрузки. Повторные уведомления о прокрутке не создают параллельные запросы.

Демо использует существующий mock API `/registry`: каждый дополнительный пакет проходит его задержку и ошибки; срезы формируются из демонстрационного набора на клиенте. Это демонстрация интерфейса, а не реализация серверного cursor API. В ДС сценарий «Ошибка подгрузки» воспроизводит неудачный первый запрос и успешный повтор.

Карточки используют нейтральное полотно, скругление `comp.table.tile.radius → sys.radius.panel`, минимальную ширину 272 px и отступ 16 px. Имя с тональной иконкой образует шапку, состояние отделено тонкой линией, числовые значения выделены ролью `type.family.data` (JetBrains Mono). Парные поля выровнены через subgrid, включая переносы длинных подписей. Цвета ошибки, предупреждения, выбора и быстрого просмотра наследуются из таблицы. Порядок полей и единые описания сохранены.

На страницах списков описание стоит рядом с заголовком через тонкий разделитель. При недостатке ширины описание переносится вниз; на телефоне действия образуют отдельную строку. Заголовки сущностей с типом и возвратом сохраняют прежнюю композицию.

## Таблица и плитки · 16 ноября 2026

Два представления одного реестра. Таблица предназначена для сравнения значений по столбцам; плитки — для чтения отдельного ресурса, его состояния, связей и показателей. Выбор вида через общий Menu находится справа, рядом с обновлением, и остаётся доступным при массовом выборе. Представление меняется сразу, без анимации перестановки ресурсов.

| Функция                   | Контракт обоих представлений                                                                                                                                                                            |
| ------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Поиск и фильтры           | Один запрос и набор типизированных условий; в плитках доступ ко всем полям через общую панель фильтров, в том числе к скрытым.                                                                          |
| Сортировка                | Одна последовательность уровней. В плитках задаётся через общую панель; порядок чтения — слева направо, сверху вниз.                                                                                    |
| Группировка               | Один набор групп и счётчиков. Группа занимает всю ширину сетки. Свёрнутое состояние сохраняется при переключении вида.                                                                                  |
| Выбор и массовые действия | Выбор по ID общий, включая другие страницы и свёрнутые группы. Чекбокс страницы выбирает только доступные элементы этой страницы. Панель действий занимает прежнее место.                               |
| Пагинация                 | Общая страница и выбранный размер порции. Смена вида не отправляет пользователя на первую страницу.                                                                                                     |
| Настройки полей           | В таблице «Столбцы таблицы», в плитках «Поля плиток». Видимость, порядок и описания общие. Ширина меняется границей заголовка только в таблице; в панели нет числового ввода.                           |
| Просмотр и ссылки         | Свободная область строки или плитки, Enter и пробел открывают быстрый просмотр. Имя и другие ссылки ведут на страницы. Чекбоксы, подсказки и меню не вызывают просмотр. Фокус возвращается к источнику. |
| Загрузка и обновление     | Первый запрос показывает скелетоны выбранного вида. Обновление сохраняет ресурсы и выбор; ошибка обновления показывает прежние данные с сообщением. Переключение вида не делает сетевой запрос.         |
| Пустота и ошибка          | Пустой реестр, отсутствие совпадений и ошибка первой загрузки остаются разными состояниями с соответствующим действием.                                                                                 |

В плитке закреплены имя и действия, остальные видимые поля следуют установленному порядку. Числа получают акцент шрифтом `sys.type.family.data` и насыщенностью `sys.type.weight.data`; единицы сохраняют Onest. Пояснение поля берётся из того же `description`, что и в заголовке таблицы и настройках. Мягкий фон ошибки или предупреждения наследуется от таблицы; при выборе остаётся цветной маркер. Просматриваемый ресурс сохраняет подсветку.

Сетка адаптивна: минимум 288 px, далее равные колонки; в более узкой области одна плитка занимает доступную ширину. Между плитками 12 px, внутри 16 px. Токены `comp.table.tile.*` доступны в инспекторе таблицы и включены в экспорт Figma. Геометрия проходит ref → sys → comp; цвета фона, границ, выбора и семантических состояний общие с таблицей. Тема меняет цвета, а не структуру.

В портале вид сохраняется для каждого реестра и рабочей области в текущей сессии, включая перезагрузку. Старые или неизвестные значения восстанавливаются как таблица. TableSelect сохраняет табличный сценарий выбора. В каталоге ДС оба вида работают во всех семи демонстрационных состояниях.

Топологическая схема полезна для зависимостей сети и размещения, но ей нужны свой масштаб, связи и правила выбора. Канбан не подходит как общий вид облачных ресурсов: перетаскивание между статусами создавало бы ложное ожидание изменения состояния ВМ. Эти представления не добавляются как декоративные переключатели.

## Колонка действий · 0.6.9

Служебная колонка имеет фиксированную ширину 48 px: общая кнопка sm 32 px и два отступа по 8 px. Свободная ширина таблицы достаётся ведущему столбцу данных. Заголовок «Действия» визуально скрыт, но остаётся доступным для скринридера и настроек столбцов. В ДС и в портале действует один контракт DataColumn.utility. Основная таблица ВМ использует меню действий; таблицы дисков и сетей — существующую одиночную кнопку.

## Действия строки и пагинация · 0.6.8

Свободная область строки открывает быстрый просмотр ресурса. Enter и пробел выполняют то же действие, когда сфокусирована сама строка. Ссылки открывают страницы, чекбоксы выбирают строки, кнопки и меню сохраняют собственное поведение. Нажатия с модификаторами, выделение текста и события из всплывающего меню не активируют просмотр. TableSelect сохраняет выбор нажатием на строку.

Отдельной кнопки с глазом нет. В демо ВМ открываются по строке, а имя ведёт на внутреннюю страницу. Диски и сети также открывают просмотр по строке; их названия показаны обычным текстом, поскольку отдельных страниц для этих сущностей в демо пока нет. Ссылка на подключённую машину продолжает вести в её ресурсы. В ДС ссылка имени открывает отдельное представление того же образца; возврат сохраняет поиск, настройки и выбранные строки.

Открытая в просмотре строка сохраняет фон наведения во всех ячейках, включая закреплённые. Выбор чекбоксом и смысловые тона ошибки/предупреждения сохраняют прежний приоритет. Закрытие окна снимает подсветку просмотра и возвращает фокус к исходной строке без прокрутки.

Актуальная пагинация описана в начале документа: общий навигатор с кнопками 36 × 36 px и выбором расположения. Подписи счётчиков и номера страниц — 14 px через `comp.table.footer-font-size` → `sys.type.size.body`. Высота строки данных остаётся 40 px. Внешняя рамка и внутренняя сетка таблицы сохранены.

## Состояния данных

В каталоге ДС переключатель над образцом показывает семь сценариев. Все реестры демо используют тот же DataTable и собственный цикл запроса к мок-серверу.

| Сценарий               | Представление                                                          | Доступное действие                         |
| ---------------------- | ---------------------------------------------------------------------- | ------------------------------------------ |
| Данные загружены       | Строки и обычная навигация                                             | Обновить данные                            |
| Первая загрузка        | Скелетоны по сетке колонок, сохранённые заголовки и границы            | Поиск и настройка представления            |
| Обновление             | Строки и выбор остаются на месте, кнопка показывает облачный загрузчик | Повторный запрос блокируется до завершения |
| Пустой реестр          | Значок, объяснение и создание первого ресурса                          | Создать ресурс                             |
| Нет совпадений         | Отдельное сообщение о поиске или условиях                              | Сбросить условия                           |
| Ошибка первой загрузки | Сообщение вместо строк, без ложного пустого результата                 | Повторить загрузку                         |
| Ошибка обновления      | Ранее полученные строки, предупреждение и сохранённый выбор            | Повторить                                  |

Обновление находится справа от инструментов таблицы, в отдельной постоянной ячейке панели. Массовый выбор заменяет только область поиска и действий: кнопка обновления остаётся видимой, геометрия панели не меняется. Нижняя навигация первой загрузки сохраняет высоту, но не показывает недостоверные числа. Повтор из сообщения переводит фокус на постоянную кнопку обновления. При смене страницы устаревший ответ запроса игнорируется.

Скелетон использует общий Skeleton, сообщения — Message и TableEmptyState, кнопки — Button. В обеих темах размер символа пустого состояния задаётся `comp.table.state-symbol-size`. Измеряемая высота предупреждения — параметр компоновки во время выполнения, а не дизайн-токен: она зависит от переноса текста. Демонстрационный сценарий «Пустой реестр» возвращает пустой ответ, сохраняя сами ресурсы. Однократная «Ошибка обновления таблицы» не расходуется фоновым опросом облака.

В «Среде демонстрации» доступны задержка, пустой реестр, постоянная ошибка загрузки и ошибка следующего обновления. В ДС загрузка удерживается для изучения до выбора другого примера; из обычного состояния обновление воспроизводит живой переход.

Один составной компонент `TableToolsPanel` используется в каталоге ДС и во всех реестрах BASIS Cloud. `TableToolbarActions` задаёт одинаковые кнопки открытия. Приложение определяет названия и типы полей, доступные значения, проверку условий и результат поиска. Внешний вид и поведение редактирования принадлежат общей библиотеке.

## Композиция и наследование

Все четыре инструмента — фильтры, сортировка, группировка и столбцы — используют отделённое правое окно `ContextPanel` с представлением `drawer`: ширина 480 px, высота `100dvh − 32 px`, внешние отступы 16 px и радиус 20 px. Панель окружена воздухом со всех сторон. На узком экране её ширина ограничивается `100vw − 32 px`; внешний отступ сохраняется. Фильтр отдельной колонки открывается в том же окне.

Заголовок и нижние действия закреплены; прокручивается только содержимое. В нижней части одна и та же сетка для всех инструментов: сброс и счётчик, затем «Отмена» и «Применить». Поиск столбцов и добавление условий не меняют положение панели или кнопок. Прокрутка фоновой страницы заблокирована с сохранением места под её полосу прокрутки.

Фон мягко затемняется: 18% в светлой теме и 32% в тёмной, через `comp.context-panel.drawer-backdrop` → `sys.color.overlay.subtle`. Ширина, внешние отступы и радиус задаются `comp.context-panel.drawer-width`, `drawer-inset` и `drawer-radius`. Радиус связан с `sys.radius.workspace`, который используется и в компоновке приложения. С версии 0.6.6 быстрый просмотр ВМ в ДС и демо, дисков и сетей использует это же окно. Его положение не зависит от строки или кнопки открытия. CascadeSelect сохраняет контекстное окно `popover`.

Условия фильтра собраны в две колонки «Поле / Условие», значение или диапазон — ниже на полную ширину. Уровень сортировки использует тот же ритм: номер и действия сверху, два поля ниже. Значения применяются только по «Применить». «Отмена», Escape и нажатие на затемнённый фон закрывают панель без сохранения черновика и возвращают фокус к кнопке открытия.

Внутри используются обычные Button, IconButton, Input, Select и Checkbox. Их цвета, размеры, состояния, фокус и загрузка определяются собственными токенами. Фильтры не создают новые стили базовых компонентов.

| Токен композиции                         | Смысловая связь            | Назначение                                       |
| ---------------------------------------- | -------------------------- | ------------------------------------------------ |
| `comp.table-tools.background`            | `sys.color.surface.subtle` | Фон условия, уровня сортировки и скрытой колонки |
| `comp.table-tools.border`                | `sys.color.border.default` | Граница групп                                    |
| `comp.table-tools.radius`                | `sys.radius.control`       | Скругление групп, 8 px                           |
| `comp.table-tools.rule-padding`          | `sys.space.md`             | Отступ внутри условия, 12 px                     |
| `comp.table-tools.rule-gap`              | `sys.space.md`             | Расстояние между условиями, 12 px                |
| `comp.table-tools.column-padding-block`  | `sys.space.sm`             | Вертикальный отступ строки, 8 px                 |
| `comp.table-tools.column-padding-inline` | `sys.space.md`             | Горизонтальный отступ строки, 12 px              |

Все связи ведут через смысловой слой к исходным значениям. Цветовые роли меняются с темой, геометрия остаётся общей. Эти семь параметров доступны для редактирования в разделе таблиц рядом с токенами контекстной поверхности. CSS технических окон не переопределяется в приложении.

## Условия и состояния

| Тип        | Условия                                    | Представление                                                              |
| ---------- | ------------------------------------------ | -------------------------------------------------------------------------- |
| Текст      | Содержит, равно, начинается с, не содержит | Текстовое поле; без учёта регистра                                         |
| IP         | Начинается с, равно                        | Префикс или полный адрес                                                   |
| Число      | Диапазон, равно, не меньше, не больше      | Числовое поле; две границы с единицами для диапазона                       |
| Дата       | Диапазон, равно, не раньше, не позже       | Календарные поля; конечный день включён целиком                            |
| Справочник | Любое из, ни одно из                       | Множественный выбор с поиском; выбранные значения объединяются через «ИЛИ» |

Между полями действует «И». Пустой список условий означает отсутствие ограничений. Новое незаполненное условие блокирует применение; ошибочный диапазон даёт пояснение. В открытом диапазоне достаточно одной границы. Счётчики вариантов справочника в демо учитывают поиск и остальные валидные условия, исключая само поле.

При открытии из заголовка виден только фильтр этой колонки. Сброс в этом окне не удаляет другие условия. Общий фильтр позволяет выбрать любое фильтруемое поле, включая скрытое. Счётчик внизу показывает результат всего набора условий.

## Сортировка и столбцы

Сортировка содержит нумерованные уровни, поле, направление, перемещение вверх/вниз и удаление. Новый уровень выбирается явно. Направления соответствуют типу: алфавит, величина или дата. Скрытое сортируемое поле отмечается пояснением. Пустые значения остаются в конце.

Настройки столбцов содержат поиск по названию и пояснению, счётчик видимых полей и действие «Показать все». Закреплённые поля нельзя скрыть или переместить; остальные можно переставлять, в том числе пока они скрыты. Полный порядок сохраняется отдельно от видимости. Скрытие не удаляет фильтр, сортировку или группировку. Числового ввода ширины и выбора плотности в панели нет.

Все четыре окна используют изолированный черновик. «Отмена», Escape и закрытие отбрасывают изменения. «Применить» переносит их в таблицу. Кнопка сброса изменяет только черновик. После закрытия фокус возвращается к кнопке открытия.

## Пояснения колонок

Необязательное `description` — единый источник текста. В демо оно задаётся в определении `RegistryColumn`, в каталоге — в `columnDescriptions`. Один текст передаётся в заголовок DataTable и в настройки столбцов; закреплённые колонки тоже показывают пояснение. У колонки без описания нет кнопки ⓘ. Сортировка и фильтр остаются независимыми действиями: нажатие на пояснение не меняет порядок строк и условия.

Подсказка открывается по наведению и фокусу, связывается с кнопкой через `aria-describedby` и закрывается по Escape. Для интерактивного заголовка с пояснением действует нижняя граница ширины: `comp.table.header-min-width` → `sys.table.header.min-width` → `ref.size.table.header.min-width`, 160 px. Длинное название сокращается; области кнопок не пересекаются. Стандартные ширины компактного реестра: имя 224, состояние 184, связь и адрес 168, число 160, действия 48 px. Высоты строк 40 и заголовков 44 px сохранены.

## Группировка

Выбирается одно поле и направление групп. «Без группировки» возвращает плоский список. Для чисел предлагается порядок по величине, для дат — хронологический, для текста и справочников — по подписи. Даты объединяются по местному календарному дню; числа — по точному значению. Пустое значение образует последнюю группу «Не задано» при обоих направлениях. Для справочника идентичность задаёт исходное значение, а подпись берётся из справочника: одинаковые подписи не смешивают разные ресурсы. Составные многозначные поля можно исключить через `groupable: false` (например, метки ВМ).

Порядок обработки: поиск и фильтры → сортировка ресурсов → формирование и упорядочивание групп → пагинация. Внутри каждой группы сохраняются уровни сортировки. Заголовок показывает общий размер группы после фильтров; для части группы выводится «На странице: X из Y». Счётчик в окне учитывает тот же набор данных.

Каждую группу можно свернуть; отдельная команда сворачивает или разворачивает все группы на текущей странице. Групповой чекбокс выбирает только доступные строки этой группы на текущей странице, включая свёрнутые. Частичный выбор виден через промежуточное состояние. Выбор на других страницах сохраняется, сворачивание не снимает отметки. При смене поля группы раскрываются. Общий выбор в заголовке охватывает текущую страницу. Сброс группировки сохраняет поиск, фильтры, сортировку и выбранные ресурсы.

В реестрах поле и направление сохраняются с представлением. Старые настройки без группировки совместимы; удалённые или недоступные поля отбрасываются при восстановлении. Оформление заголовков и строки управления задают пять токенов `comp.table.group-*`; они наследуют общие поверхности, текст и размеры. Приложение передаёт данные и счётчики, а групповые строки, кнопки и выбор принадлежат DataTable.
