# Визуальный разбор · 0.7.4

Цель — уменьшить число конкурирующих акцентов, сохранить плотность инженерного интерфейса и согласовать портал с общей ДС. Палитра BASIS и существующие скруглённые поверхности сохранены.

## Решения

| Область              | Изменение                                                                                               | Зачем                                                           |
| -------------------- | ------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------- |
| Шапка                | Компактный знак A из логотипа BASIS и строка Basis statix; имя и роль пользователя; тема внутри профиля | Название читается без тяжёлого словесного логотипа              |
| Возврат              | Кнопка «Назад» слева от блока типа и имени, с общей высотой; компонент Button заполняет контекст        | Единая композиция и предсказуемое место возврата                |
| Заголовки            | В реестрах нет надзаголовка; в карточках тип сущности — ссылка на её список                             | Имя остаётся главным, список доступен прямо из контекста        |
| Типографика          | Onest для интерфейса, IBM Plex Mono для точных технических значений; две роли в токенах и образцах ДС   | Технические данные различимы без лишних цветовых акцентов       |
| Бренд и путь         | Короткий нейтральный разделитель; корневое «Облако» из крошек убрано                                    | Бренд и навигация читаются отдельными блоками                   |
| Компактная навигация | Шеврон в нижнем углу, иконка на центральной оси                                                         | Наличие подпунктов видно без смещения активного пункта          |
| Питание ВМ           | Выключение и перезапуск — secondary / neutral; запуск — brand                                           | Повседневные команды не конкурируют с предупреждениями в данных |
| Подтверждения        | Фирменная основная кнопка; предупреждение текстом и Message; удаление — danger                          | Цвет действия и описание последствий выполняют разные задачи    |
| Обзор                | Убран повтор роли; статусы истории выровнены справа; успешные операции используют subtle                | Внимание остаётся на текущих проблемах и ресурсах               |
| Карточки             | Нейтральные иконки метрик; убрано бессодержательное описание в быстром просмотре ВМ                     | Числа, значения и связи заметнее декоративных элементов         |
| Состояния            | Остановка и удаление в процессе — info; обязательность API-параметра — neutral                          | Штатный процесс и обязательное поле не выглядят аварией         |
| Служебные страницы   | Заголовки «Состояние платформы» и «Потребление ресурсов» берутся из каталога разделов                   | Меню, путь и заголовок называют одну страницу одинаково         |
| Наложения            | Tooltip фоновой кнопки не появляется поверх открытого Menu                                              | Один активный слой взаимодействия                               |

Внешние поля и сетка портала, рамки колонок, стабильная панель массового выбора, вкладки внутри сущностей, избранное и плавающие консоли сохранены. Геометрия кнопок и меню определяется общими компонентами. Новых универсальных компонентов нет.

## Цветовая иерархия

- Фирменный тёмно-синий выделяет основную команду; голубой обозначает выбор, ссылки и активный процесс.
- Вторичные операции и декоративные иконки используют нейтральные роли.
- Зелёный обозначает нормальное состояние или завершение, без обязательной яркой подложки у каждого события.
- Янтарный остаётся у реальных предупреждений: высокая нагрузка, блокировка, обслуживание и последствия операции. Красный — у ошибок и удаления.
- Цвет всегда сопровождается подписью; состояние ресурса не меняет цвет всей навигации.

## Охват проверки

Все 49 разделов каталога открыты в браузере с ожиданием загрузки: аккаунты и группы, вычисления, хранение, сети, SDN, инфраструктура, доступ, эксплуатация и инструменты. Для каждого проверены наличие главного заголовка, отсутствие надзаголовка и горизонтального переполнения всей рабочей области при 1440 × 960. [Наблюдения по разделам](../design/previews/section-audit-0.7.4.json) содержат результат этой проверки; это проверка маршрутов и геометрии DOM, а не утверждение о просмотре каждого возможного состояния.

Визуально отдельно проверены общие композиции: обзор, таблица ресурсов, карточки ВМ/аккаунта/сети, форма настройки, инструменты таблицы и быстрый просмотр. Шапка и меню проверены в обеих темах, при полном и компактном меню, на узком экране. Автоматические проверки перечислены в [verification.md](verification.md).

Снимки: [карточка и новая шапка](../design/previews/statix-header-light-0.7.4.png), [тёмная тема](../design/previews/statix-header-dark-0.7.4.png), [Onest и IBM Plex Mono](../design/previews/statix-typography-0.7.4.png). Проверены переход по надзаголовку, возврат с восстановлением области, совпадение высоты кнопки с блоком заголовка и живое изменение шрифтовой роли через инспектор.

## Границы

Выбор языка демонстрирует будущий сценарий. Реализован русский интерфейс; English недоступен с пояснением. Новая шапка не добавляет авторизацию или выход из реальной сессии. Профиль и операции используют существующий мок-движок. UI-примеры Menu и SplitButton находятся в соответствующих разделах каталога ДС.
