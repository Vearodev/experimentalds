# Функциональная карта демо · 0.7.0

Источник: локальный проект Базис.DynamiX (`apiserver`). Внешний вид исходного портала не переносится: сохранены BASIS, Onest, светлая и тёмная темы, скруглённые секции, общие компоненты ДС и плавающая консоль.

Инвентаризация: **238 записей маршрутов**, **1200 операций OpenAPI**, **1187 уникальных путей**. У одного пути могут быть разные HTTP-методы. Маршруты legacy и нового портала пересекаются; это не число отдельных экранов.
В демо: **49 разделов предметной области** и **18 типов вложенных сущностей**, плюс обзор и профиль. Это не реализация всех операций API: полный каталог методов доступен как справочник.

## Осознанное переосмысление

- Аккаунт → ресурсная группа → ресурсы. Общие реестры и рабочие области равноправны. Область можно выбрать в меню или открыть из карточки аккаунта/группы.
- Старый маршрут `projects` сохранён для совместимости избранного; в интерфейсе это ресурсные группы. `clusters` теперь означает зоны платформы; Kubernetes — отдельная сущность.
- Площадки, зоны и узлы находятся в инфраструктуре; физические и виртуальные GPU, PCI, DPDK и VF-пулы не смешиваются с виртуальными машинами.
- ViNS и SDN имеют отдельные модели и реестры. Между их идентификаторами нет неявных соответствий.
- Диск принадлежит аккаунту. Дополнительный диск можно подключить к ВМ другой ресурсной группы того же аккаунта.
- Административная доступность, блокировка изменений и состояние питания ВМ разделены.
- Все реестры используют ResourceTable: общие окна фильтров, сортировки, группировки, колонок и быстрого просмотра. Описание поля едино для заголовка и настроек колонок. Видимые колонки выбираются по назначению конкретного реестра.
- Внутри сущности — горизонтальные вкладки; в основной навигации — вертикальные группы. Избранное сохраняет маршрут, вкладку и рабочую область; порядок меняется перетаскиванием.
- Карточка ресурса даёт переходы по связям, квоты и аудит. Профиль не занимает отдельную группу в большом меню.

## Реализованные сценарии

- Создание и изменение ресурсов через общий механизм форм: типизированные значения, ссылки, зависимые списки, числовые диапазоны, проверка перед отправкой, ошибки с сохранением ввода.
- ВМ: создание с выбором аккаунта, группы, образа, политики хранения, узла, ViNS и параметров виртуализации; питание, пауза/возобновление, снимки, диски, размещение, безопасность, консоль, удаление и восстановление.
- Kubernetes: конфигурация, сеть, плагин, лимиты узлов и создание начальной worker-группы. Группы узлов имеют самостоятельную форму.
- Сети: ViNS, NAT, маршруты и резервирование адресов; группы безопасности с зависимостью портов от протокола; SDN с проверкой группы доступа.
- Хранение: политики, SEP и пулы, диски, изменение размера, лимиты I/O, целевая политика реплики и демонстрационное состояние синхронизации.
- Балансировщики: фронтенды, бэкенды и серверы; группы сервисов и их связанные сущности.
- Права: три демонстрационные роли, ограничение аккаунта, серверные проверки изменений; роли API с выбором методов. Пароли не попадают в состояние, задачи и аудит.
- Задачи выполняются с задержкой, дают результат и допускают повтор. Массовые операции проверяют весь набор; перед удалением связи проверяются повторно. Корзина восстанавливает сущности, ВМ и её системный диск.
- Обзор, использование ресурсов, здоровье платформы, аудит, задачи, служебные задания, инциденты и справочник 1200 API-операций.

## Границы демонстрации

- Исходный проект не изменяется; его сервисы не запускаются. HTTP API демо и автономный режим используют один MockEngine. Реальные RPC, сети, гипервизоры, Kubernetes, SSH/VNC и системы хранения не подключены.
- Поля и формы — продуктовая модель для обсуждения UX, не готовый контракт интеграции. ID демо строковые; реальные API используют числовые ID и UUID. Единицы и названия параметров потребуют адаптера при реализации продукта.
- Состояния репликации, групп сервисов и Kubernetes моделируются. Передача блоков, развёртывание worker-ВМ, kubeconfig, реальные журналы Zero Access и выдача учётных данных не выполняются.
- Демо хранит одно активное подключение диска. Флаг общего доступа показан как характеристика; многократное подключение и полный жизненный цикл shared snapshots требуют отдельного сценария.
- Отчёт показывает текущие выделенные ресурсы. Исторический биллинг/метринг, планировщик размещения, affinity-правила, аварийные миграции, сервисные операции площадки и весь набор 1200 методов не симулируются.
- Digital Energy в исходнике — промо-страница внешнего продукта. Она не перенесена в рабочую навигацию облака. Swagger заменён локальным справочником без отправки запросов.
- Новые компоненты ДС не добавлялись. Добавлены только композиции приложения; у существующих Select, TableSelect и NumberInput уточнено отображение обязательности поля.
