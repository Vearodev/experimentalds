# BASIS Cloud · демонстрационное приложение 0.7.0

## Наполнение карточек · 0.7.1

ВМ получила отдельные блоки конфигурации, размещения, подключения и защиты. Типовые карточки всех сущностей используют общую иерархию параметров и связей. Подробные настройки не повторяют служебные поля; счётчики связей и вложенные реестры согласованы с правами доступа. Светлая и тёмная темы используют существующие токены и компоненты ДС.

Подробности: [внутренние страницы ресурсов](resource-pages.md).

Демонстрация применяет компоненты дизайн-системы в связанных рабочих сценариях. Это локальный продуктовый прототип, а не подключение к гипервизору. Каталог ДС и облачное приложение используют один `@basis/ui`, один граф токенов, Onest и общий переключатель тем. Изменённые в мастерской токены действуют и в облаке.

## Функциональная структура · 0.7.0

Визуальная концепция демо сохранена. Из `apiserver` взяты предметная модель, связи, маршруты и описания API. Подробная карта всех 49 разделов и 18 вложенных сущностей: [platform-reference.md](platform-reference.md).

Основная навигация: аккаунты и ресурсы; вычисления; хранение; сети ViNS; SDN; инфраструктура; доступ; эксплуатация; инструменты. Общий поиск работает по разделам и ресурсам. Выбор рабочей области ограничивает реестры аккаунтом или ресурсной группой. Профиль и среда демонстрации вынесены в служебные действия.

Внутри сущности используются вкладки существующей ДС: обзор, связанные реестры, настройки, доступ, квоты и аудит по назначению. Карточки показывают ссылки на связанные записи. Из карточки аккаунта и группы можно переключить рабочую область. Старые маршруты `projects` и `clusters` сохранены для избранного; подписи теперь «Ресурсные группы» и «Зоны».

Все реестры разделяют один ResourceTable с фильтрами по типу данных, сортировкой, группировкой, настройками колонок, быстрым просмотром, массовыми операциями и состояниями загрузки/пустоты/ошибки. Для каждого раздела задан осмысленный набор видимых колонок. Размеры и оформление инструментов задаёт ДС.

Формы проверяют обязательность, диапазоны и совместимость ресурсов. Для сложных форм есть шаг проверки. Kubernetes выбирает конфигурацию, политику, ViNS и начальную worker-группу; диск — аккаунт, политику и лимиты I/O. Сетевые правила учитывают протокол, семейство адресов и диапазоны портов. Изменения попадают в журнал задач и аудит; удаление проверяет связи, корзина позволяет восстановление.

Мок-движок проверяет режим администратора, владельца аккаунта и наблюдателя. Это демонстрация взаимодействий, не механизм промышленной авторизации: все данные синтетические и доступны локальному движку. Реальные системы виртуализации, Kubernetes, SDN и хранилища не подключены. Методы API в справочнике не выполняются.

## Открыть

- `npm run dev` → http://127.0.0.1:5173/#cloud/overview. Vite обслуживает интерфейс и настоящий HTTP мок-API.
- `npm run build`, затем `npm run preview` → http://127.0.0.1:4173/#cloud/overview. Тот же API работает с production-сборкой.
- `cloud-demo.html` открывается непосредственно с диска. Он содержит шрифты, логотип, интерфейс и встроенный движок демонстрации. `playground.html` открывает каталог компонентов; из него можно перейти в облако.

Локальные серверы слушают только loopback. Остановка — Ctrl+C. Файлы сборки создаются командой `npm run build`.

## Единый реестр 0.6

Одинаковые инструменты у ВМ, дисков, сетей, хостов, журнала задач, подключённых дисков и снимков ВМ. Колонка задаёт отображение, исходное значение, тип фильтра, единицу измерения и допустимые границы. Внешний вид ячейки не используется для сортировки и сравнения.

- Текст: содержит, равно, начинается с, не содержит. Поиск работает также по скрытым полям и названиям связанных сущностей.
- Справочник: любое из выбранных значений или исключение. Варианты показывают количество ресурсов в текущей области.
- Число: диапазон, равенство, нижняя или верхняя граница. VLAN ограничен 1–4094.
- IPv4/CIDR: полный адрес или префикс; сортировка числовая.
- Дата: день или период, включая весь конечный день в местном часовом поясе.
- Условия соединяются через И. Панель показывает ожидаемое количество результатов до применения. Быстрые выборки используют этот же фильтр.
- Сортировка по заголовку, Shift для дополнительных полей; отдельная панель задаёт приоритет и направление.
- Колонки можно скрыть и переставить. Идентификатор и действия закреплены. Шириной и плотностью пользователь не управляет.
- Поиск и массовые действия находятся в одном слоте фиксированной высоты. Выбор сохраняется при фильтрации и смене страницы; число выбранных вне страницы указано явно.
- Поиск, фильтры, колонки, сортировка и страница сохраняются отдельно для каждого реестра и области в sessionStorage. Повреждённые и устаревшие настройки очищаются при чтении.
- В инфраструктуре доступны зоны и реестр узлов; внутри зоны используется тот же реестр узлов.

Модель: `registry-model.ts`. Общая композиция: `ResourceTable.tsx`. Прикладные страницы описывают поля, связи и действия. Таблица `@basis/ui` отвечает за геометрию, выбор, заголовки и базовые кнопки.

## Формы и состояния

Создание ВМ проверяет уникальность имени в проекте, доступность хоста, квоты проекта и вместимость хоста, соответствие сети/дисков проекту, свободные адреса, CIDR, MAC и метки. Статический IP должен принадлежать выбранной подсети; сетевой и broadcast-адреса исключаются. Подсети внутри одного проекта не пересекаются. При смене проекта зависимые поля сбрасываются.

Черновик формы хранится в sessionStorage. Ошибка API не очищает введённые значения. Итоговая конфигурация показана перед отправкой, расход квоты — рядом с формой. Дополнительные параметры свёрнуты в Accordion; ошибки внутри раскрывают секцию. InputTag принимает допустимый черновик при уходе из поля, а недопустимый оставляет для исправления.

В таблице строка 40 px, заголовок 44 px; колонки отделены рамками. Стандартные ширины реестра ВМ получаются из `comp.table.column.*`. Пользователь меняет только видимость и порядок. Поиск и настройки вида сохраняются отдельно для проекта/кластера. При выборе строк содержимое уже существующей панели заменяется массовыми действиями, геометрия таблицы сохраняется. Скрытые поиском выбранные строки учитываются явно. Операция доступна, если применима ко всем выбранным машинам; частичного молчаливого выполнения нет.

Загрузка использует Skeleton; фоновые операции — Progress и облачный индикатор. Ошибки доступны в Message и журнале, завершения — в Toast. Ошибочная ВМ имеет мягкую красную подсветку строки, высокая нагрузка — предупреждающую. Смысл передаётся также текстом и значком.

## Мок-сервер

`domain.ts` задаёт сущности, начальные данные и валидацию. `mock-engine.ts` — общий движок операций. `server.ts` подключает его как middleware к Vite dev/preview; `api.ts` — транспорт клиента.

Начальные данные: 16 машин, 3 проекта, 3 кластера, 5 хостов, 3 сети и связанные диски. Есть выключенные машины, ошибка, высокая нагрузка и хост на обслуживании.

В HTTP-режиме состояние сохраняется в `.local/cloud-demo.json`, запись выполняется через временный файл и переименование до успешного ответа. Очередь запросов предотвращает конкурирующие записи; состояние переживает перезапуск. Изменение связей выполняется после валидации всего действия.

В автономном файле работает тот же движок без HTTP. Сборка помечена как embedded, поэтому её можно также открыть через статический сервер (`/cloud-demo.html`) без облачного API. Состояние сохраняется в `basis-cloud-demo-v1` в localStorage, если браузер разрешает хранилище для `file:`; иначе остаётся в памяти до закрытия. Браузерное и серверное состояния независимы.

Задачи имеют время старта/завершения. Чтение состояния продвигает их прогресс и применяет результат; клиент опрашивает API, пока виден или имеет активные задачи. Это симуляция фонового выполнения без отдельного worker-процесса. Повтор создаёт новую запись истории и заново проверяет состояние ресурсов.

| Метод и путь после `/api/demo`            | Действие                                                          |
| ----------------------------------------- | ----------------------------------------------------------------- |
| GET `/state`                              | Снимок состояния и продвижение задач                              |
| POST `/vms`                               | Создание ВМ, системного диска, резервирование IP/ресурсов         |

| DELETE `/vms/:id/volumes/:volumeId`       | Отключение дополнительного диска выключенной машины               |
| POST `/volumes`, `/networks`, `/projects` | Создание ресурсов                                                 |
| DELETE `/volumes/:id`, `/networks/:id`    | Удаление свободного ресурса                                       |

## Сценарии для дизайн-ревью

1. Создать машину: выбрать проект и хост, изменить профиль ресурсов, добавить свободный диск, проверить итог. После отправки наблюдать создание и итог в журнале.
2. В «Среде демонстрации» включить ошибку следующего запроса. Отправить заполненную форму, проверить сообщение и сохранённые значения, повторить.
3. Выделить несколько машин одного состояния. Сравнить панель действий и положение таблицы до/после выбора. Добавить машину другого состояния и проверить доступность операций.
4. У выключенной ВМ изменить CPU/RAM, подключить и отключить дополнительный диск. Системный диск отключить нельзя.
5. Включить ошибку следующей фоновой задачи, создать снимок. Открыть журнал, повторить операцию и проверить отдельную запись результата.
6. Создать пустой проект, затем сеть и ВМ в его рабочей области. Проверить пустые состояния и переходы между общим реестром и областью проекта.
7. Переключить тему; проверить формы, таблицы, меню и окна на узком экране. В мастерской изменить токен и вернуться в демо для проверки общего визуального языка.

## Границы

Нет реального гипервизора, сетевого трафика гостевых систем, авторизации/RBAC, отправки уведомлений, настоящего резервного копирования или выполнения shell-команд. Консоль отвечает только на заранее заданные учебные команды. Профиль и код подтверждения искусственные. Фильтрация и пагинация работают в клиенте на полном небольшом наборе данных; виртуализация и серверная пагинация требуют отдельной продуктовой реализации.
